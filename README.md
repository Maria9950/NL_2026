## Порядок работы

Каждая задача выполняется в отдельной ветке. Формат имени ветки: `<номер темы>_task_<номер задачи>_<язык>`, например `1_task_1_kotlin`. Исходные файлы размещаются в папке соответствующей темы: `<папка темы>/task_<номер>_<язык>/`.

## Тема 1. Многопоточность

**Папка:** `1_threads/`

| № | Задание | Язык | Ветка |
|---|---|---|---|
| 1 | Параллельное вычисление суммы квадратов | Kotlin | `1_task_1_kotlin` |
| 2 | Моделирование работы касс | Ruby | `1_task_2_ruby` |
| 3 | Параллельный поиск минимума и максимума | Rust | `1_task_3_rust` |
| 4 | Параллельный анализ массива | Groovy | `1_task_4_groovy` |

**1.1. Параллельное вычисление суммы квадратов (Kotlin).**  
Создать массив целых чисел и разделить его на четыре части. Четыре потока независимо вычисляют суммы квадратов элементов своих частей; главный поток ожидает их завершения и объединяет частичные результаты. Итог сравнивается с результатом последовательного вычисления. Для суммы используется 64-битный целочисленный тип.

**1.2. Моделирование работы касс (Ruby).**  
Создать очередь заказов, каждый из которых содержит сумму покупки. Три потока-кассира извлекают заказы из общей очереди и обрабатывают их. Программа подсчитывает выручку каждого кассира и общую выручку; обновление общего счётчика защищено механизмом синхронизации. После обработки всех заказов потоки корректно завершают работу.

**1.3. Параллельный поиск минимума и максимума (Rust).**  
Разделить непустой массив целых чисел между несколькими потоками. Каждый поток находит минимальный и максимальный элементы своей части. Главный поток ожидает завершения работы, определяет общие минимум и максимум и сверяет их с последовательным поиском.

**1.4. Параллельный анализ массива (Groovy).**  
Создать четыре потока для независимого анализа одного массива целых чисел. Потоки подсчитывают количества положительных, отрицательных, чётных и нечётных элементов соответственно. Главный поток ожидает завершения всех вычислений и выводит результаты. Ноль считается чётным, но не относится к положительным или отрицательным числам.

## Тема 2. Алгоритмические задачи

**Папка:** `2_algorithms/`

| № | Задание | Язык | Ветка |
|---|---|---|---|
| 1 | Сортировка слиянием (рекурсия) | Haskell | `2_task_1_haskell` |
| 2 | Подсчёт элементов вложенного списка (рекурсия) | Scheme | `2_task_2_scheme` |
| 3 | Проверка достижимости в графе (рекурсия) | Prolog | `2_task_3_prolog` |
| 4 | Проверка правильности скобочной последовательности | OCaml | `2_task_4_ocaml` |

**2.1. Сортировка слиянием (Haskell, рекурсия).**  
Реализовать рекурсивную сортировку списка целых чисел по возрастанию. Список разделяется на две части, каждая из которых сортируется рекурсивно, после чего отсортированные части объединяются. Готовые функции сортировки не использовать.

**2.2. Подсчёт элементов вложенного списка (Scheme, рекурсия).**  
Реализовать рекурсивный обход списка, элементы которого могут быть вложенными списками. Подсчитать количество атомарных элементов на всех уровнях вложенности. Пустые списки не учитываются как атомарные элементы. Для запуска использовать реализацию Scheme (Guile).

**2.3. Проверка достижимости в графе (Prolog, рекурсия).**  
Задать ориентированный граф набором фактов о рёбрах. Создать рекурсивный предикат, определяющий, существует ли путь от указанной начальной вершины к конечной. Предусмотреть обработку циклов с помощью учёта посещённых вершин, чтобы поиск завершался и в графах с циклами.

**2.4. Проверка правильности скобочной последовательности (OCaml).**  
Программа получает строку со скобками трёх видов: `()`, `[]`, `{}`. Проверить правильность их порядка и вложенности с помощью стека, реализованного на списке. Вывести результат проверки; предусмотреть пустую строку и ошибочные последовательности.

## Тема 3. Ввод/вывод в консоль и файл

**Папка:** `3_io/`

| № | Задание | Язык | Ветка |
|---|---|---|---|
| 1 | Учёт посещаемости студентов | Perl | `3_task_1_perl` |

| 3 | Статистика текстового файла | Standard ML | `3_task_3_sml` |
| 4 | Сортировка товаров по цене | D | `3_task_4_d` |

**3.1. Учёт посещаемости студентов (Perl).**  
Прочитать текстовый файл журнала, в котором каждая запись содержит имя студента, дату и отметку присутствия (`1` — присутствовал, `0` — отсутствовал). Для каждого студента определить количество посещений, пропусков и процент посещаемости. Вывести отчёт в консоль и записать его в отдельный текстовый файл.

**3.2. Калькулятор с историей вычислений (Lua).**  
Реализовать консольный калькулятор, выполняющий сложение, вычитание, умножение и деление двух чисел. После вычисления выводить результат и сохранять запись операции в текстовый файл. Предусмотреть команды просмотра истории и завершения работы, а также обработку некорректного ввода и деления на ноль.

**3.3. Статистика текстового файла (Standard ML).**  
Прочитать указанный текстовый файл и вычислить число строк, непустых строк и слов. Словами считать последовательности символов, разделённые пробельными символами. Вывести статистику в консоль и сохранить её в отдельный текстовый файл.

**3.4. Сортировка товаров по цене (D).**  
Прочитать текстовый файл, содержащий названия товаров и их цены в формате `название;цена`. Отсортировать записи по возрастанию цены. Вывести отсортированный список в консоль и сохранить его в новый файл; некорректные записи обрабатывать с сообщением об ошибке.

## Тема 4. Клиент-серверное взаимодействие

**Папка:** `4_client_server/`

Все четыре задания предполагают отдельные программы клиента и сервера, написанные на одном соответствующем языке. Соединение устанавливается локально через TCP (`127.0.0.1`), без внешних API и веб-фреймворков. Клиент отправляет текстовый запрос, сервер возвращает ответ. Предусмотреть корректную обработку ошибочных запросов.

| № | Задание | Язык | Ветка |
|---|---|---|---|
| 1 | Сетевой калькулятор | Scala | `4_task_1_scala` |
| 2 | Сетевой преобразователь регистра текста | Clojure | `4_task_2_clojure` |
| 3 | Сетевая проверка палиндрома | Erlang | `4_task_3_erlang` |
| 4 | Сетевой конвертер температуры | Elixir | `4_task_4_elixir` |

**4.1. Сетевой калькулятор (Scala).**  
TCP-клиент отправляет серверу два числа и арифметическую операцию (`+`, `-`, `*`, `/`). Сервер выполняет вычисление и возвращает числовой результат либо сообщение об ошибке, в том числе при делении на ноль. Клиент выводит полученный ответ в консоль.

**4.2. Сетевой преобразователь регистра текста (Clojure).**  
TCP-клиент отправляет строку и команду `UPPER` или `LOWER`. Сервер преобразует переданный текст соответственно в верхний или нижний регистр и возвращает преобразованную строку клиенту. При неизвестной команде сервер отправляет сообщение об ошибке.

**4.3. Сетевая проверка палиндрома (Erlang).**  
TCP-клиент передаёт серверу строку, содержащую латинские буквы и пробелы. Сервер проверяет, является ли строка палиндромом без учёта регистра букв и пробелов, и возвращает ответ `YES` или `NO`. Клиент отображает ответ в консоли.

**4.4. Сетевой конвертер температуры (Elixir).**  
TCP-клиент отправляет серверу числовое значение температуры в градусах Цельсия. Сервер переводит его в градусы Фаренгейта по формуле `F = 1.8 * C + 32` и возвращает результат. Некорректные значения обрабатываются с сообщением об ошибке.

## Тема 5. Конвертация данных из одного формата в другой

**Папка:** `5_convert/`

| № | Задание | Язык | Ветка |
|---|---|---|---|
| 1 | TSV → HTML | Common Lisp | `5_task_1_lisp` |
| 2 | JSON → CSV | F# | `5_task_2_fsharp` |
| 3 | CSV → SQL | Julia | `5_task_3_julia` |
| 4 | INI → JSON | Nim | `5_task_4_nim` |

**5.1. Преобразование TSV в HTML (Common Lisp).**  
Прочитать текстовый файл с таблицей, в котором поля разделены символами табуляции. Преобразовать содержимое в HTML-документ с таблицей: первая строка исходного файла используется как заголовок, остальные — как строки данных. Экранировать специальные HTML-символы и сохранить результат в файл. Поля с табуляциями внутри значений не рассматриваются.

**5.2. Преобразование JSON в CSV (F#).**  
Прочитать JSON-файл с массивом однотипных плоских объектов и преобразовать его в CSV-таблицу. Ключи объектов становятся заголовками столбцов, значения — ячейками. Корректно обрабатывать запятые, двойные кавычки и переводы строк внутри строковых полей CSV. Использовать стандартные средства платформы .NET для чтения JSON.

**5.3. Преобразование CSV в SQL (Julia).**  
Прочитать CSV-файл с заголовком и числовыми столбцами. На основе строк сформировать текстовый SQL-файл с командами `INSERT INTO` для заранее заданной таблицы. Имена столбцов должны быть допустимыми SQL-идентификаторами. Формат входного CSV ограничен числовыми значениями без разделителей внутри полей; сторонние CSV-библиотеки не используются.

**5.4. Преобразование INI в JSON (Nim).**  
Прочитать INI-файл, содержащий секции `[имя]` и пары `ключ=значение`, и преобразовать его в JSON-объект. Каждая секция представляется вложенным объектом; значения параметров сохраняются как строки. Пустые строки и строки комментариев игнорируются. Для обработки использовать стандартные модули Nim; файл начинается с объявления секции, многострочные значения не поддерживаются.
